## 1 目的

数据安全工具箱针对企业数据安全检测与审计的“可发现、可处理、可审计、可度量”目标进行规划与设计，提供基于统一插件化检测引擎的数据安全能力，包括数据资产识别、敏感数据（PII/密钥/YARA）检测、文件元数据分析、PCAP 协议分析与流量分析、威胁情报、事件关联与安全告警、报告输出等，能够同时满足企业数据安全合规需求与实际运维分析需求，及时有效发现异常与违规事件，是企业数据安全日常管理工作的重要支撑平台。

本作业指导书的编写目的是指导测评实施人员、运维人员与安全分析人员在现场实际开展数据安全工具箱的部署、配置、使用与维护工作，并根据工作的深入开展及时更新本指导书，以保证指导书的高指导性。

## 2 适用范围

本手册适用于在现场测评实施、数据安全运营与平台运维中负责数据安全工具箱部署、配置、检测、分析与维护的相关人员。

## 3 职责

### 3.1 部署实施人员

1. 部署实施人员应在客观、公正的情形下，按照测评双方相互认可的部署方案，基于明确定义的部署方式和解释实施部署活动；
2. 部署实施人员应正确理解部署项，并具有良好的判断；
3. 部署实施人员应注意测评记录和证据的接收、处理、存储和销毁，保护其在测评期间免遭改变和遗失，并保守秘密；
4. 部署实施人员应遵循正确的部署方法进行现场部署和结果判定，以确保满足相关标准的要求；
5. 部署实施人员在完成现场部署并填写完各类检查表后，应检查确认内容填写完整无误，签字确认，并将检查表交给被测方配合人员确认并签字。

## 4 安装部署

本章主要讲解平台部署与升级过程中的流程、注意事项、准备工作以及操作步骤。

### 4.1 注意事项

- 部署前务必确认 `.env` 中已配置强口令：`SECRET_KEY`（≥32 位随机字符）、`POSTGRES_PASSWORD`、`ADMIN_PASSWORD`、`PROBE_BOOTSTRAP_TOKEN`；
- 本地 HTTP 环境设置 `COOKIE_SECURE=false`，生产 HTTPS 部署请设为 `true`；
- `PRESIDIO_ENABLED` 默认关闭，避免首次调用下载数百 MB spaCy 中文模型阻塞 worker；需 Presidio 中文 PII 时设为 `true` 并预置模型；
- 高流量接口会触发后端 429 背压（`QUEUE_PENDING_MAX` / `QUEUE_OLDEST_PENDING_SECONDS`），应按目标主机实际流量调整；
- 探针以 root 手动运行时 dumpcap 会降权，spool 目录需可写（`chmod 777` 或由运行用户属主）。

### 4.2 部署前准备

#### 4.2.1 环境要求

为保证系统长期稳定运行，应保证电源有良好的接地措施、防尘措施、保持使用环境的空气通畅和室温稳定，建议环境温度 10-35℃、湿度 35%-80%。平台的安放、使用和报废应遵照国家相关法律法规要求。

#### 4.2.2 软硬件要求

后端基于 Docker Compose 运行，需要 Docker 与 Docker Compose；前端为 Vue 3 + Element Plus + ECharts；数据库 PostgreSQL 16、缓存 Redis 7。探针需 Python 3.11+（`tomllib`、`datetime.UTC`）、`requests`、`psutil`，以及 `dumpcap`（优先）或 `tcpdump`。分析引擎依赖 tshark / Zeek / Suricata / nmap。

### 4.3 部署模式（在线 / 单机）

- 复制环境变量模板并填写强口令：`cp .env.example .env`；
- 构建并启动：`docker compose build`、`docker compose up -d`；
- 初始化管理员与系统设置：`docker compose exec backend python scripts/seed.py`；
- 后端容器启动时自动执行 `alembic upgrade head` 建表（迁移已做幂等处理，可安全重建）。

访问入口：前端 `http://localhost:8080`（nginx 代理 `/api/` 到后端 `:8000`）；后端 API `http://localhost:8000`；OpenAPI `http://localhost:8000/docs`。

### 4.4 探针部署

探针部署在受监控主机，负责抓包、资产端口采集与目标文件采集。安装与运行：

- 安装探针（创建 dstprobe 用户、systemd 服务、配置目录）：`cd probe && sudo ./install.sh`；
- 编辑配置 `/etc/data-security-toolbox/probe.toml`，配置 `[server] url`、`[capture] interface`、`[agent] bootstrap_token` 等；
- 启动 / 重启：`sudo systemctl restart data-security-toolbox-probe`；
- 手动运行：`python3 probe.py --config /etc/data-security-toolbox/probe.toml`。

探针行为：首次注册返回 `probe_id + token` 并写入身份文件（0600），重启不轮换；抓包分片原子落盘 spool，认证上传 `/api/v1/pcaps/upload`，失败指数退避；心跳上报 CPU/内存/捕获速率/上传状态；`asset_loop` 上报开放端口与 banner；`file_loop` 上传目标文件内容触发敏感检测。

### 4.5 离线部署

- 在线环境准备离线包：`python scripts/offline_bundle.py`；
- 目标内网：`docker load < security-toolbox-images.tar`、`docker compose up -d`、`docker compose exec backend alembic upgrade head`、`docker compose exec backend python scripts/seed.py`；
- 启动集成组件：`docker compose -f docker-compose.yml -f docker-compose.integrations.yml --profile integrations up -d`。

## 5 配置指南

本章按功能模块介绍数据安全工具箱的配置与使用。

### 5.1 首页介绍（安全驾驶舱）

用户登录平台后默认进入安全驾驶舱。默认主页可查看资产概况、风险/事件/告警总览、检测结果、敏感数据、引擎状态、存储概况、队列状态、探针在线情况等。

| 面板 | 说明 |
|---|---|
| 资产概况 | 查看 IT 资产数量、高风险资产、敏感数据资产等。 |
| 风险 / 事件趋势 | 查看风险趋势、事件趋势、等级分布。 |
| 检测结果 / 告警 | 查看检测中心结果与告警总览。 |
| 敏感数据 | 查看敏感数据类目聚合（PII / 密钥 / YARA）。 |
| 引擎状态 | 查看各检测引擎（tshark/Zeek/Suricata/Sigma 等）可用性与规则数。 |
| 存储 / 队列 | 查看存储占用、队列 pending/running 状态。 |

系统支持对面板信息的自定义，用户可通过勾选关注卡片确定首页展示内容。

### 5.2 数据接入与采集

平台通过探针采集、文件上传、PCAP 上传与外部引擎接入实现对多源数据的采集与解析。

#### 5.2.1 探针采集

探针在被监控主机上抓包并分片上传，同时上报开放端口、banner 与目标文件内容，为网络分析与资产识别提供数据源。

#### 5.2.2 PCAP 上传

在【网络分析→PCAP 工作台】上传 `.pcap` / `.pcapng`，后台自动创建分析任务，用 tshark 解析并跑规则引擎；也可通过 `POST /api/v1/pcaps/upload` 上传。

#### 5.2.3 文件上传

在【资产与数据安全→文件分析】上传单个文件做元数据分析与敏感检测；探针 `file_loop` 也可自动上传目标文件内容。

#### 5.2.4 集成适配器

通过 Integration Adapter Layer 接入 Zeek、Suricata、Presidio、MISP、Wazuh/osquery、OpenSCAP，解析外部引擎日志并统一输出 DetectionResult。

### 5.3 资产与数据资产管理

#### 5.3.1 资产中心

资产中心提供 IT 资产总览，支持按资产组、时间范围（最近 24 小时 / 7 天 / 30 天 / 自定义）筛选，查看资产风险等级、开放端口、banner、关联漏洞与资产关系图。

#### 5.3.2 数据资产

数据资产模块对敏感数据分类、资产关系与风险等级进行管理，识别主机、IP、服务、数据库等数据资产。

#### 5.3.3 资产关系图

以图形化方式展示资产之间的网络与数据关系，便于整体掌握资产拓扑与暴露面。

### 5.4 网络分析

| 模块 | 功能 |
|---|---|
| PCAP 工作台 | 上传/解析 PCAP，查看协议分布、五元组、数据包分层树 + 原始字节、TCP 流跟踪（stream follow）、异常标记。 |
| 会话流探索 | 全局会话流（五元组、包数、字节、时间），支持协议/IP/端口筛选。 |
| 协议分析 | 全局协议分布（TCP/HTTP/RESP/TLSv1.2/MySQL 等）。 |
| 实时流量 | 探针心跳驱动的实时指标（捕获速率、上传状态）。 |

### 5.5 敏感数据检测

数据引擎对上传文件与 PCAP 中的真实字节做 PII / 密钥 / YARA 检测，检出结果在【资产与数据安全→敏感发现】聚合展示。

| 规则 | 等级 | 说明 |
|---|---|---|
| DATA_SECRET_001 | Critical | 密钥 / 口令等敏感数据。 |
| DATA_PII_001 | High | 身份证 / 手机号 / 银行卡 / 邮箱等个人信息。 |
| DATA_YARA_001 | High | 恶意文件特征（如 eicar）。 |

### 5.6 告警与事件

| 模块 | 功能 |
|---|---|
| 告警中心 | 告警列表、详情、关联资产/IOC/数据资产，支持告警处置（确认 / 清除 / 归档）、告警流 SSE。 |
| 安全事件中心 | incident_engine 按时间、资产、IOC、攻击链聚合 Finding 为 Incident。 |
| 检测中心 | 全部检测结果（DetectionResult），含引擎、规则、严重级、置信度、证据、建议、风险评分。 |
| 风险分析 | 风险评分、等级、趋势分析。 |

### 5.7 威胁情报

| 模块 | 功能 |
|---|---|
| IOC 情报 | IOC 列表与关联（资产 / 检测 / 事件）。 |
| CVE 漏洞 | CVE 离线清单与关联。 |
| 检测规则 | Sigma / YARA / Suricata 规则管理（新增 / 编辑 / 启用 / 禁用 / 检索）。 |
| 离线资源 | 规则、IOC、CVE、模型安全导入与版本管理。 |

### 5.8 安全引擎

平台内置统一插件化检测引擎，并支持接入外部引擎，检测结果统一输出。

| 引擎 | 说明 |
|---|---|
| 资产引擎 asset_engine | 资产识别、端口 / 服务 / banner、弱口令 / 弱认证检测（如 ASSET_DB_WEAK_AUTH_001）。 |
| 数据引擎 data_engine | 敏感数据（PII / 密钥 / YARA）检测。 |
| 协议引擎 protocol_engine | 协议分析、异常 User-Agent 等（如 PROTO_HTTP_UA_001）。 |
| 流量 / 规则引擎 | 流量特征、规则匹配（如 NET_SCAN_001、NETWORK_PORT_SCAN）。 |
| 风险 / 合规引擎 | 风险评分、合规审计。 |
| 事件关联引擎 incident_engine | 按时间 / 资产 / IOC / 攻击链聚合事件。 |
| 外部引擎 Zeek / Suricata / Sigma / Wazuh / osquery / OpenSCAP | 外部引擎状态与日志解析。 |

### 5.9 算法评估

【工具→算法评估】提供商用密码应用安全性评估（GB/T 39786）与代码算法时间复杂度分析（前端自包含工具），支持在线评估与结果导出。

### 5.10 报表管理

【运维管理→报告中心】可按检测 / 事件 / 风险范围生成 HTML / PDF / CSV 报告并下载；也可通过 `POST /api/v1/reports/generate` 与 `GET /api/v1/reports/{id}/download` 用 API 生成。

### 5.11 系统管理

| 模块 | 功能 |
|---|---|
| 探针管理 | 探针注册 / 在线状态 / 指标 / 心跳，支持资产分析。 |
| 任务中心 | 异步任务列表、任务详情、队列状态。 |
| 健康状态 | 系统健康、各引擎规则数、存储用量、队列状态、探针概况。 |
| 离线资源 | 离线规则 / IOC / CVE / 模型导入与版本管理。 |

## 6 运维管理

本章主要讲解平台的日常运维管理，为管理员例行维护以及简单故障排除提供指导。

### 6.1 日常运维注意事项及高危操作

| 风险操作 | 风险级别 | 风险说明 | 风险应对 |
|---|---|---|---|
| 恢复出厂设置 | 高风险 | 删除平台所有数据与配置，对有数据合规要求（等保保留 180 天日志）的客户影响极大。 | 谨慎操作，操作前务必备份。 |
| 修改后端关键配置 / 重启容器 | 高风险 | 可能导致服务暂不可用。 | 在业务低峰期操作并提前备份。 |
| 关闭唯一启用网口 / 接口 | 高风险 | 可能导致设备无法登录。 | 联系运维 / 售后工程师处理。 |
| 高流量下触发背压 | 中风险 | 接口返回 429，影响采集。 | 按目标流量调整 QUEUE_PENDING_MAX 等参数。 |

### 6.2 数据备份

平台数据存储于 Docker 卷（`postgres_data`、`redis_data`、`backend_data`），可通过 Docker 卷备份与数据库导出进行备份，建议定期备份以保障数据合规与可恢复。

## 7 升级管理

### 7.1 规则 / IOC / CVE / 模型升级

通过【系统→离线资源】或 `POST /api/v1/integrations/offline/upload`、`POST /api/v1/integrations/offline/import` 安全导入离线规则、IOC、CVE 与模型包，支持版本管理，不使用任意路径。

### 7.2 系统升级

系统升级通过重新构建镜像并滚动更新容器完成：`docker compose build` 后 `docker compose up -d`。升级前请备份数据，并确认数据库迁移（`alembic upgrade head`）正常执行。
