# 2026-09-16 缺陷修复

工作目录：`source`。旧 `dist-deploy` 目录和 ZIP 保持原样，部署时应使用当前源码构建的镜像。

## 修复内容

- 探针目录采集：任务 658 在 `/home/kali` 报 Permission denied，任务 656 无法读取 `/root`。服务将 `ProtectHome` 改为 `read-only`，增加仅用于读取/目录遍历的 `CAP_DAC_READ_SEARCH`，仍以 dstprobe 运行、保持只读系统保护和不跟随符号链接的采集范围限制。无法访问单个目录不再终止其他目录的采集。此权限允许探针读取普通账户原本无权读取的文件，执行范围仍由管理员下发的采集目录控制。
- 网络扫描：平台与探针默认 200 个端口；平台对指定网段逐地址执行扫描，避免存活预探测漏掉仅开放其他端口的主机。页面去除底层工具名称，并继续提供显式端口与执行探针选择。
- 检测规则：新增 Suricata 明文私钥传输基线及 YARA 私钥/云凭据基线；基线同时进入规则列表和实际检测。YARA 按 UTF-8 内容编译，修复 Windows 中文规则路径读取问题。
- 前端：CVE 服务端分页、总数、页大小及搜索重置；保留旧 API 不传 page 时的数组响应。中文分页控件、CVE 中文描述优先、统一 SVG 图标尺寸。PCAP 告警证据改为独立弹窗。
- `.env.example`：补充 `DEPLOYMENT_BACKEND_URL` 用途、地址格式与示例。地址必须可从探针访问；不是 Docker 内部名称，不包含 `/api/v1`。自签证书才需要 CA 文件。
- 网络 DLP：命中敏感传输时保存原始二进制，详情展示 SHA256、哈希范围、前 4096 字节的十六进制/ASCII 预览和完整捕获字节下载。片段哈希不会标为完整文件哈希。原始字节单独落盘，列表与告警仍只携带元数据。历史 PCAP 需重新分析才产生字节证据。
- 资产详情 500：运行日志显示 PostgreSQL 在提取 JSON 证据字段时拒绝 `\u0000`。写入层将 NUL 表示为可见的 `\x00`，迁移 `0013_safe_json_evidence` 修复历史 JSON，保留记录及原本的字面转义字符串。
- 探针部署：`probe/install.sh`、systemd 单元与 `offline/load-images.sh` 在本机 Windows 检出（`core.autocrlf=true`）下带 CRLF，远端 bash 在第 2 行即失败：`set: pipefail : invalid option name`，删除探针后再添加会一直停在 INSTALLING。现在 `.gitattributes` 强制 `*.sh`/`*.service` 为 LF；探针包构建统一以 LF 写出文本成员并补齐可执行位（Windows 无 POSIX 权限位，此前包内 `install.sh` 是 0666，手工 `sudo ./install.sh` 会 Permission denied）；部署侧解包后再兜底清理 CR 并校验，因此旧包也仍可安装。
- 探针重新入网：`install.sh` 为升级需要保留 `probe.identity.json`，而探针原先「本地已有身份就不再注册」，于是新部署下发的一次性入网令牌永远不会被消费——删除探针后在添加会一直停在 90%「service started; awaiting registration」，直到 5 分钟回调超时判失败。实机（Kali 192.168.191.130）确认：平台记录为 `CALLBACK_TIMEOUT`，探针进程健康但心跳用已注销的 `probe_id` 收到 401（心跳 401 被静默吞掉，只有 `inventory_loop` 每 30 秒打印一次 `HTTPError`）。现在平台推送的 `bootstrap_token + deployment_id` 优先于旧身份，探针会重新入网并替换身份；若令牌已消费/失效且本地仍有身份，则退回本地身份而不是退出让 systemd 反复重启。修复后重启探针 1 秒内身份由 `probe_id 1` 换为 `2`，部署转为 ONLINE / 100%。
- 探针服务未重启：平台用 `--install-only` 装完包就直接 `systemctl start`，而重试/升级时探针服务本来就在运行，`systemctl start` 对已运行的 unit 是空操作，新代码与新配置从未生效。实机确认：磁盘上的 `probe.py` 已是新版、`probe.toml` 已是新配置，但 `MainPID` 仍是 3 小时前的老进程，日志继续刷 401。现改为 `systemctl restart`，并在 `tests/deployment/test_registration_flow.py` 断言不再出现 `systemctl start`。
