# 探针任务停止、删除与数据资产采集改进

## 使用方法

- 在「任务中心」或「探针管理 → 详情 → 关联任务」停止探针扫描、数据资产采集任务。
- 等待中的任务停止后不再下发。已经领取的任务由探针 3.3.1 每约 3 秒检查停止状态，当前文件读取或网络请求结束后退出；旧版探针可能继续执行，但平台会忽略停止后的结果。
- 终态任务可以删除；从任务列表移除，保留关联采集数据与内部记录，以识别迟到报告。
- 任务不再处于 Pending/Running 后即可删除探针。删除平台探针记录本身不会卸载远程服务；需要把主机上的探针文件一并清理时，见 [probe-removal.md](probe-removal.md)（控制台「删除」默认勾选卸载主机探针，会先清理主机再删除记录）。
- 等待领取超过 15 分钟自动失败；执行超过配置时限加 120 秒回传宽限自动失败。后台每分钟检查，打开任务列表时也会检查。失败任务不会重复下发。

## 数据资产采集

- 按探针、完整路径和资产类型合并记录，避免同名文件覆盖。
- 仅在完整扫描的目录及深度范围内标记未发现的历史文件；不影响其他目录和数据库端点。
- TSV 按制表符解析，JSONL 支持多行记录，压缩 SQL 有界解压；文本支持 UTF-8 与 GB18030。
- JSON/JSONL 字段分析结合少量值样本与字段名，只回传类目和计数。
- 跳过符号链接，文件数量与目录数量分别限额，避免重叠目录重复采集。
- 无效目录、读取失败、停止及超时不会被当作完整扫描。
- 远程配置的空目录列表继承探针本地目录；平台表单仍建议明确填写采集路径，并可设置 5–1800 秒时限。
- 先上传平台任务报告，再执行定时采集，避免待上传结果被覆盖。

文件内容最多抽样 2 MiB，小文件计算 SHA256；检测属于抽样盘点，不能保证发现整个文件内的所有敏感数据。数据库端点检测仅检查本机常用端口是否监听，不连接数据库读取表结构。原始文件内容及敏感值不上传。

## 升级

平台重新构建 backend、worker、beat、deployment-worker 和 frontend 镜像后启动，无新增数据库迁移。探针默认包版本为 3.3.1，amd64/arm64 构建产物位于本地 `probe_packages/probe-3.3.1/`。

在「探针部署」页重新部署完整 3.3.1 包。必须包含 `probe.py`、`scanner.py` 和 `data_assets.py`；不要仅替换单个文件。平台任务停止和删除立即可用，远程协作停止及采集改进需要升级探针后生效。
