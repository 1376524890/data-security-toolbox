# 数据安全工具箱（Data Security Toolbox）部署与运行手册

> 本文档基于当前代码库（`develop` 分支）整理，覆盖**完整功能、从零部署、探针部署、主动扫描、密码评估、API、常见问题**。按本文操作可在干净环境完整部署并运行。

---

## 1. 项目简介

面向企业内网（含离线）环境的数据安全检测与安全审计综合平台。统一插件化检测引擎 `engine/core` + 资产/协议/流量/数据/风险/合规/威胁情报引擎，并通过 `Integration Adapter Layer` 接入 Zeek、Suricata、Presidio、MISP、Wazuh/osquery、OpenSCAP，检测结果统一输出 `DetectionResult`。

### 1.1 架构

```
Probe Agent(采集) ──▶ 上传文件/资产/PCAP ──▶ Celery 任务 ──▶ 后端分析服务 ──▶ PostgreSQL ──▶ 前端展示 ──▶ 报告
```

- **Probe Agent**：单进程、低资源，仅负责采集（抓包/资产/文件）、本地 spool、认证上传、心跳与轻量资产清单。
- **Backend Analysis Platform**：FastAPI + Celery + PostgreSQL + Redis，负责解析、检测、调度、存储、报告。
- **Vue Management Console**：Vue 3 + Element Plus + ECharts。

### 1.2 技术栈

| 组件 | 技术 |
|---|---|
| 后端 | FastAPI + Celery + SQLAlchemy + Alembic |
| 数据库 | PostgreSQL 16 |
| 缓存/队列 | Redis 7 |
| 前端 | Vue 3 + Element Plus + ECharts + Vue Router + Pinia |
| 探针 | Python 3.11+（`tomllib`/`datetime.UTC`）+ requests + psutil + dumpcap/tcpdump |
| 外部引擎 | tshark / Zeek / Suricata / nmap |

### 2.2 核心能力

- **数据资产识别**：主机、IP、服务、数据库资产、敏感数据分类、资产关系与风险等级。
- **元数据分析**：JPG/PNG/PDF/DOCX 元数据、文件类型、SHA256、隐藏信息检测。
- **主动网络扫描（新增）**：`POST /api/v1/scan` 触发 nmap 主动发现（`-sn`）与主机服务/版本枚举（`-sV`），结果写入资产并进入资产/合规/威胁情报(CVE)流水线。
- **商用密码评估**：GB/T 39786 合规性/正确性/有效性评估，支持**从探针自动识别并填充**（`GET /api/v1/crypto/probe-profile`）。
- **代码算法复杂度分析**：acorn AST + 启发式估算时间/空间复杂度。
- **协议/流量分析**：PCAP/PCAPNG 上传、tshark/dpkt 解析、协议树 + 原始字节、TCP 流跟踪、异常/端口扫描检测。
- **外部引擎**：Zeek、Suricata 日志自动解析；tshark 为核心解析器。
- **集成适配器**：Zeek JSON/TAB、Suricata eve.json、Presidio 中文 PII、MISP IOC、osquery/Wazuh、OpenSCAP。
- **事件关联**：`incident_engine` 按时间、资产、IOC、攻击链聚合 Finding 为 Incident。
- **离线资源中心**：规则、IOC、CVE、模型安全导入与版本管理。
- **安全审计 / 任务 / 报告 / 管理控制台**：HTML/PDF/CSV 报告、异步任务、探针管理、威胁情报、离线资源。

## 4. 从零开始部署（在线/单机）

### 4.1 获取代码并准备 `.env`

```bash
git clone <你的仓库地址> data-security-toolbox
cd data-security-toolbox

cp .env.example .env
# 编辑 .env，必须设置以下强口令：
#   SECRET_KEY          >=32 位随机字符串
#   ADMIN_PASSWORD     管理员密码（登录前端/后端）
#   POSTGRES_PASSWORD  PostgreSQL 密码
#   PROBE_BOOTSTRAP_TOKEN  探针注册引导令牌（探针安装时要用）
```

`.env` 关键变量：

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `APP_ENV` | 否 | `production` | `production` 时启用管理员认证与探针令牌校验 |
| `SECRET_KEY` | **是** | - | 会话签名密钥，≥32 字符 |
| `ADMIN_USERNAME` | 否 | `admin` | 管理员用户名 |
| `ADMIN_PASSWORD` | **是** | - | 管理员密码 |
| `POSTGRES_DB` | 否 | `security_toolbox` | 数据库名 |
| `POSTGRES_USER` | 否 | `security` | 数据库用户 |
| `POSTGRES_PASSWORD` | **是** | - | 数据库密码 |
| `PROBE_BOOTSTRAP_TOKEN` | **是** | - | 探针注册引导令牌 |
| `HTTP_PORT` | 否 | `8080` | 前端对外端口 |
| `PCAP_RETENTION_DAYS` | 否 | `7` | PCAP 保留天数 |
| `QUEUE_PENDING_MAX` | 否 | `200` | 队列背压阈值 |
| `ALERT_SUPPRESS_WINDOW_SECONDS` | 否 | `300` | 告警抑制窗口 |

### 4.2 构建并启动

```bash
docker compose build
docker compose up -d
```

启动的服务：`postgres`、`redis`、`backend`（API :8000）、`worker`（Celery）、`beat`（调度）、`frontend`（nginx :8080）、`flower`（Celery 监控，仅内部端口）。

> backend 容器启动时自动执行 `alembic upgrade head` 建表（幂等）。`COOKIE_SECURE=false` 用于本地 HTTP；生产 HTTPS 请设 `true`。`PRESIDIO_ENABLED=false` 关闭 Presidio 模型下载（避免首次下载数百 MB spaCy 模型）；需要中文 PII 时置 `true` 并预置模型。

### 4.3 初始化管理员与平台设置

```bash
docker compose exec backend python scripts/seed.py
```

### 4.4 访问

- 前端：`http://localhost:8080`（nginx 代理 `/api/` 到后端 `:8000`）
- 后端 API：`http://localhost:8000`
- 健康检查：`GET http://localhost:8000/api/v1/health`

用 `.env` 中的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。

### 4.5 验证部署

```bash
curl -s http://localhost:8000/api/v1/health | python3 -m json.tool
# 期望 status=ok，database/redis/celery 均 ok
```

## 5. 探针部署与运行（每台受监控设备）

探针部署在**受监控主机**，负责抓包、资产采集与目标文件采集。

### 5.1 安装

```bash
cd probe
sudo ./install.sh
```

install.sh 会：
- 创建系统用户 `dstprobe`
- 拷贝 `probe.py`、`requirements.txt` 到 `/opt/data-security-toolbox/probe/`
- 创建 `/etc/data-security-toolbox/` 配置目录与 `/var/lib/data-security-toolbox/spool` spool 目录
- 生成默认 `probe.toml`
- 安装并启动 systemd 服务 `data-security-toolbox-probe`

### 5.2 配置 `probe.toml`

```bash
sudo vi /etc/data-security-toolbox/probe.toml
```

```toml
[server]
url = "http://<平台IP>:8000"     # 后端地址
verify_tls = false               # 本地 HTTP 为 false；HTTPS 为 true

[capture]
interface = "eth0"               # 受监控网卡
segment_seconds = 30
segment_max_mb = 64

[spool]
path = "/var/lib/data-security-toolbox/spool"
max_mb = 2048
retention_seconds = 86400

[agent]
heartbeat_seconds = 30
asset_interval_seconds = 900
file_interval_seconds = 0        # >0 且 paths 非空时采集目标文件内容
bootstrap_token = "<PROBE_BOOTSTRAP_TOKEN>"   # 与 .env 的 PROBE_BOOTSTRAP_TOKEN 一致
ports = [22, 80, 443, 445, 3306, 5432, 6379, 8080]
paths = []                       # 目标文件目录（可选）
max_files = 50
demo = false
```

### 5.3 启动 / 重启

```bash
sudo systemctl restart data-security-toolbox-probe
sudo systemctl status data-security-toolbox-probe
```

### 5.4 验证探针已注册

在「探针管理」页或通过 API 查看：

```bash
curl -s -X POST http://<平台>:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<ADMIN_USERNAME>","password":"<ADMIN_PASSWORD>"}' \
  -c /tmp/cookie.txt
curl -s -b /tmp/cookie.txt 'http://<平台>:8000/api/v1/probes?page_size=100'
```

### 5.5 Python 3.11+ 注意事项（重要）

探针使用 `tomllib` 与 `datetime.UTC`，**要求 Python 3.11+**。若系统默认 Python 过旧（如 Ubuntu 20.04 的 3.8），install.sh 生成的 systemd 服务会因解释器过旧而启动失败（日志报 `probe has no identity and no bootstrap token` 或 import 错误）。

解决办法：改用 python3.11+（如 miniconda），并修改服务文件 `ExecStart` 指向该解释器：

```bash
sudo vi /etc/systemd/system/data-security-toolbox-probe.service
# 将 ExecStart 改为：
#   ExecStart=/path/to/python3.11+/bin/python3 /opt/data-security-toolbox/probe/probe.py --config /etc/data-security-toolbox/probe.toml
# 若解释器在 /home 下且服务有 ProtectHome=true，需改为 ProtectHome=false
sudo systemctl daemon-reload && sudo systemctl restart data-security-toolbox-probe
```

> ⚠️ **权限坑**：`/etc/data-security-toolbox` 目录必须由 `dstprobe` 用户可进入。若该目录属主是 `root` 且权限 `0700`，dstprobe 将读不到 `probe.toml` 与 `probe.identity.json`（报 "no identity and no bootstrap token"）。修复：
> ```bash
> sudo chown dstprobe:dstprobe /etc/data-security-toolbox
> sudo chmod 0700 /etc/data-security-toolbox
> ```

> 以 root 手动运行探针时，dumpcap/tcpdump 会降权，spool 目录需可写；生产用 `dstprobe` + `CAP_NET_RAW` 时由属主解决。

## 6. 主动网络扫描（信息安全评估）

系统默认只做**被动**分析（抓包/文件）。新增了**主动扫描**：发现存活主机、枚举开放服务与版本，写入资产并进入资产/合规/威胁情报(CVE)流水线。

扫描有两种执行位置，可在「资产中心」直接选择：

| 来源 | 执行位置 | 适用场景 |
|---|---|---|
| 平台扫描 | worker 容器（nmap `-Pn -sT`，缺失/被拒时自动切换到内置 TCP-connect 引擎） | 平台能路由到目标网段 |
| 探针扫描 | 目标网段内的探针主机（无特权 TCP-connect） | 平台与目标网段隔离，或需要避开容器 NAT/透明代理 |

> 注意：若扫描路径存在透明代理/NAT 拦截（连 `192.0.2.1` 等保留地址都被应答），平台扫描结果会附带告警
> 「扫描路径存在透明代理/NAT 拦截…请改用目标网段内的探针扫描」，此时请改用探针扫描。

### 6.1 通过 API 触发

```bash
# 登录获取 cookie
curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<ADMIN_USERNAME>","password":"<ADMIN_PASSWORD>"}' -c /tmp/c.txt

# 触发扫描（target 可为 IP / 主机 / CIDR / 范围）
curl -s -b /tmp/c.txt -X POST http://localhost:8000/api/v1/scan \
  -H 'Content-Type: application/json' \
  -d '{"target":"192.168.110.0/24","discovery":true,"top_ports":1000,"public_exposed":false}'
```

请求体字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `target` | string | **是** | 目标：IP / 主机 / CIDR / 范围，如 `192.168.1.0/24` |
| `discovery` | bool | 否 | 是否先发现存活主机（CIDR/范围时建议 true；使用 TCP-connect 探测，不依赖 ICMP） |
| `top_ports` | int | 否 | 扫描端口数（默认 1000） |
| `ports` | int[] | 否 | 显式端口列表，优先于 `top_ports`，如 `[22,80,443,3306]` |
| `public_exposed` | bool | 否 | 是否视为公网暴露（影响公网数据库/Web 判定） |
| `probe_id` | int | 否 | 指定探针执行扫描；留空则由平台/worker 执行 |

返回任务对象 `{id, status, progress, current_stage, ...}`。

轮询结果：

```bash
curl -s -b /tmp/c.txt http://localhost:8000/api/v1/scan/<task_id> | python3 -m json.tool
# status=Success 后，result.hosts 为发现主机，scanned_assets 为扫描资产
```

平台扫描产生的资产：`probe_id=null`、`extra.source="platform_scan"`；探针扫描产生的资产：`extra.source="probe_scan"`。两者都会进入资产/合规/威胁情报(CVE)流水线并生成发现与 Incident。

### 6.2 通过前端触发

「资产中心」（`/assets`）顶部有「网络扫描」卡片：输入目标 → 选择端口数 → 「开始扫描」→ 轮询结果 → 展示扫描资产。

### 6.3 说明

- 扫描在 worker 容器内执行，需 worker 可访问目标网段（Docker 默认经 NAT 可访问内网）。
- 服务/版本识别（`-sV`）较慢（视开放端口数，可能 1–5 分钟）；每台主机有 `--host-timeout`（最长 60s）上限，
  多台主机默认 4 路并发，避免单台过滤主机拖住整个网段。
- 容器内 ICMP/ARP 常被拦截，因此扫描固定使用 `-Pn -sT`；nmap 缺失或被拒时自动使用内置 TCP-connect 引擎。
- CVE 匹配依赖本地 CVE 库（离线资源）或 NVD（需 API key 与网络）。

### 6.4 通过探针采集目标服务器数据资产

探针可枚举其所在服务器的数据资产并回传平台（仅文件名、字段、敏感类目计数，不上传原始数据）。

```bash
# 下发采集任务（也可在「数据资产」页点「从探针采集数据资产」）
curl -s -b /tmp/c.txt -X POST http://localhost:8000/api/v1/probes/<probe_id>/data-assets/jobs \
  -H 'Content-Type: application/json' \
  -d '{"paths":["/srv/data","/var/www/uploads"],"max_files":200,"max_depth":3,"include_databases":true}'
```

探针在下一次 `/commands` 轮询（默认 30s）领取任务，本地采集后 `POST /api/v1/probes/{id}/data-assets` 回传；
平台按 `probe_id + 名称` 幂等入库到 `data_assets`（`source="probe:<探针名>"`），可在「数据资产」页查看与筛选。

部署探针时也可直接配置采集目录（部署表单「数据资产目录」），生成的 `probe.toml` 会包含：

```toml
[data]
enabled = true
interval_seconds = 3600
paths = ["/srv/data"]
max_files = 200
max_depth = 3
include_databases = true
allow_remote = true
```

> `paths` 为空时探针不会上报空清单（避免把已发现资产标记为消失），任务会以失败状态提示未配置目录。

## 7. 商用密码评估工具（GB/T 39786）

「算法评估」（`/algorithms`）含两个功能：

### 7.1 商用密码应用安全性评估

- 手动配置：算法、密码套件、协议版本、密钥长度、密钥管理。
- **从探针自动识别并填充**：选择探针 → 点击「从探针自动识别并填充」→ 调用 `GET /api/v1/crypto/probe-profile?probe_id=X`，聚合探针采集的服务 banner 与 TLS 握手，自动填充算法/套件/协议/密钥长度，并识别无认证/弱口令等密码风险后评估。
- 评估维度：合规性 / 正确性 / 有效性，依据 GB/T 39786、GM/T 系列标准。

### 7.2 代码算法复杂度分析

粘贴源代码 → 选择语言 → 分析复杂度（acorn AST + 启发式，输出时间/空间复杂度、函数级复杂度）。

## 12. 常见问题（FAQ）

### Q1：`docker compose build` 报 `401 Unauthorized` / `failed size validation`
Docker Hub 直连被拦时，需配置可用 registry 镜像源或代理。编辑 `/etc/docker/daemon.json` 的 `registry-mirrors`（保留可用源），并 `systemctl restart docker`。若 BuildKit 报 `failed size validation`，多为镜像源经代理返回的清单尺寸不一致，可换镜像源或清缓存 `docker builder prune -f`。

### Q2：探针注册报 `probe bootstrap token required`
生产模式下后端要求探针带 `X-Probe-Bootstrap-Token` 头且与 `.env` 的 `PROBE_BOOTSTRAP_TOKEN` 匹配。探针从 `probe.toml [agent] bootstrap_token` 读取并自动携带。若在「探针管理」页手动注册，需填入该令牌（前端已加输入框）。

### Q3：探针启动报 `probe has no identity and no bootstrap token`
见 §5.5：通常是系统 Python 过旧（需 3.11+）或 `/etc/data-security-toolbox` 目录 `dstprobe` 无法进入（`chown dstprobe:dstprobe` + `chmod 0700`）。

### Q4：扫描很慢
`nmap -sV` 服务识别较慢，属正常。可降低 `top_ports`（如 100）或减少 `discovery` 范围。

### Q5：无 CVE 命中
CVE 匹配依赖本地 CVE 库或 NVD。离线环境需通过离线资源导入 CVE；在线需配置 `NVD_API_KEY` 并确保网络可达。

### Q6：HTTPS 解密
未实现 TLS 解密（无 SSLKEYLOGFILE），仅采集 TLS 握手元数据（SNI/cipher/JA3）。

### Q7：探针部署一直停在 90%（`service started; awaiting registration`）
`current_stage` 停在 `WAIT_CALLBACK` 表示探针进程已经起来，但从未调用 `/api/v1/probes/register`。按顺序排查：

1. 目标机上 `journalctl -u data-security-toolbox-probe -n 50`。若反复出现 `probe inventory upload/scan retry: HTTPError`，说明探针正在用已注销的身份发心跳（心跳 401 不会打印日志），通常是本地残留了旧的 `/etc/data-security-toolbox/probe.identity.json`——`install.sh` 为升级需要会保留它。
2. 对比 `stat -c '%y %n' /opt/data-security-toolbox/probe/probe.py /etc/data-security-toolbox/probe.toml` 与 `systemctl show -p MainPID,ExecMainStartTimestamp data-security-toolbox-probe`：若文件是新的、进程启动时间却早于本次部署，说明服务没有被重启（旧版本平台用 `systemctl start`，对运行中的 unit 是空操作）。`systemctl restart data-security-toolbox-probe` 即可让新代码与新配置生效。
3. 入网令牌是一次性的，有效期 15 分钟。若令牌已过期，请在「探针部署」里重试或新建部署，不要手工修改 `probe.toml`。

修复后的探针会自动重新入网并替换残留身份（`bootstrap_token` + `deployment_id` 优先于本地旧身份）；若目标机上仍是修复前的探针，可临时 `rm -f /etc/data-security-toolbox/probe.identity.json` 后重新发起部署。部署成功前探针会把抓包分片留在 spool（默认上限 2 GB），重新入网后这些历史分片会被上传，必要时先清理 `/var/lib/data-security-toolbox/spool`。

## 13. 已知边界 / 限制

- **HTTPS 解密**：未实现，仅采集 TLS 握手元数据。
- **MD5**：探针计算 SHA256（`file_records` 含 md5，后端 `FileRecord` 已持久化 md5）。
- **队列背压**：高流量接口会触发后端 429（`QUEUE_PENDING_MAX` / `QUEUE_OLDEST_PENDING_SECONDS`），按目标流量调整。
- **探针心跳覆盖**：多循环 heartbeat 相互覆盖 `probe.extra`（建议后端合并 metadata，已做深度合并）。
- **扫描为手动触发**：可扩展 Celery beat 定时扫描。
