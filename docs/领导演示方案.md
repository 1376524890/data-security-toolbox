# 数据安全工具箱 · 领导演示方案（数据安全合规检查服务）

> 用途：向领导汇报「数据安全合规检查服务」时的演示脚本、讲解重点、技术问答口径与竞品对比。
> 所有"实测"结论均取自 2026-09-17 在本机生产栈（`source` 项目，8 个容器，平台 2.10.0）上的真实执行结果。

## 0. 一句话定位

**我们交付的不是一台扫描器，而是一套"可下发、可取证、可回收"的数据安全合规检查能力**：
在受检网络内部署一个只读轻量探针，由平台统一下发检查任务，把主机/目录/流量上的敏感数据与协议行为
变成可追溯的检查结果和报告，检查结束再一键把探针和它在目标主机上的全部生产文件干净回收。

## 2. 演示主线（建议 12 分钟，五幕）

### 第一幕（2 分钟）· 总览：先给结论，再讲过程

- 入口：**仪表盘**。
- 着重点：风险总览、事件趋势、引擎健康、敏感数据分布四张图一起看——**一屏说明"我们现在处于什么风险状态"**。
- 讲解口径：「这是合规检查的"体检报告首页"。风险不是拍脑袋给的，是资产权重 × 暴露面 × 数据敏感度 ×
  威胁因子 × 置信度算出来的，每一项都能下钻到证据。」
- 不要在这里纠缠细节，领导注意力最贵，第一幕只给结论。

### 第二幕（3 分钟）· 数据侧检查：我们到底查到了什么

- 入口：**数据资产 → 敏感发现 → 数据对象 → 数据类型中心**。
- 着重点：
  1. 数据资产按敏感类别、敏感度分级聚合，能看到"哪台主机、哪个目录、哪类数据"；
  2. 点进数据对象能看到**命中字段、样例（脱敏）、命中规则、置信度**——这是合规检查最常被追问的一环；
  3. 数据类型中心说明识别能力来自可维护的规则集，不是写死的正则。
- 讲解口径：「采集口径是管理员下发的目录白名单，探针只读、不跟随符号链接、有文件数/深度/单文件大小/
  运行时上限，不会把受检主机的业务拖垮。」
- 证据位置：扫描配置里能看到 `max_files=200`、`max_depth=3`、`max_runtime=300s`、XLSX 解压比上限等硬限制。

### 第三幕（3 分钟）· 探针下发：把"服务"这两个字讲实

- 入口：**探针管理 → 部署**。
- 动作：演示预检 → 下发 → 实时进度（连接、上传、安装、启动、等待注册）→ 状态变在线。
- 着重点：**这是"服务"而非"工具"的分水岭**——检查能力可以推到受检主机上，而不是把数据搬到平台。
- 讲解口径：「一台主机从零到可下发检查任务，只需要一次 SSH 凭据，30 秒内完成；凭据用后即毁，
  任务结束（含失败）立即销毁，不留明文。」
- 兜底：若现场网络不稳，可改为讲解已完成的部署记录（含每一阶段的事件时间线）。

### 第四幕（2 分钟）· 流量侧检查：把"证据"讲透

- 入口：**协议分析 → PCAP 分析**（数据包分层树 + 原始字节）→ **网络 DLP**。
- 着重点：协议分布、五元组、TCP 流跟踪、异常标记；网络 DLP 对明文 TCP/HTTP 做旁路重组，命中敏感字段、
  关键词、文件 SHA256 指纹，**证据脱敏保存**。
- 讲解口径：「结论后面永远跟着原始字节和会话，谁能质疑我们就把它还原给谁看。
  我们不做在线阻断、不解密 HTTPS——旁路检查，不改变受检网络的任何行为。」

### 第五幕（2 分钟）· 交付与闭环：结果、报告、回收

- 入口：**检测结果 → 安全事件（含 ATT&CK 映射）→ 报告中心 → 返回探针管理点"回收"**。
- 动作：现场生成一份 HTML/PDF 报告；然后对演示探针执行一次回收。
- 着重点：检查结果 → 事件聚合 → 报告交付 → **探针与生产文件回收**，全链路闭环。
- 讲解口径：「检查做完，痕迹要清干净。卸载脚本按固定白名单删除服务、systemd 单元、运行目录、
  配置与凭据、采集缓存、spool 和安装时自带的抓包工具副本；`dstprobe` 账号只有在证明是本探针创建的
  前提下才删除，共用账号默认保留。删除清单会回传到平台写进记录，**删除动作本身可审计**。」

## 3. 可能被问到的技术细节（Q&A 口径）

**Q1 探针会不会影响受检主机业务？**
不会。探针是单进程 Python 服务，以 `dstprobe` 低权限账号运行，systemd 单元带 `ProtectSystem` 等加固；
采集按管理员下发的目录白名单，只读、不跟随符号链接，且有主机/端口并发、文件数、深度、单文件大小、
总读取量、运行时上限。CPU/内存上限可在单元里再收紧。

**Q2 数据会不会出网？**
不会。平台私有化部署，规则库、CVE 库、IOC 都是本地库（本地 CVE 39.4 万条）。威胁情报源默认关闭，
需要时由管理员显式启用。探针只向平台地址回调。

**Q3 凭据怎么管的？**
SSH 凭据只在本次部署请求里出现，平台用部署密钥 AES-GCM 加密后绑定到该条部署记录，**任务结束（含失败）
立即销毁**，控制台看不到明文。凭据有 TTL。

**Q4 检出结果凭什么可信？**
每条发现都带规则 ID、引擎名、置信度、风险分与证据（命中字段/原始报文/文件哈希/原始字节），
可下钻、可回溯。审计上还有规则集版本号 + SHA256 指纹，能证明"用哪一版规则查出的结果"。

**Q5 误报怎么控制？**
多引擎交叉（资产/数据/协议/流量/日志/威胁情报共 15 个引擎）、规则带置信度、风险分做加权；
规则集支持版本发布与回滚（当前 `default` 规则集 146 条规则，已发布版本带 SHA256）。

**Q6 大文件、大 PCAP 会不会把平台拖死？**
扫描配置对文件数、目录深度、单文件大小、总读取量、运行时都有硬上限，大文件走采样；
PCAP 侧有索引/分片与流重组限制。超限是"按配置降级"，不是崩溃。

**Q7 支持哪些协议/数据格式？**
网络侧：TCP 流重组、HTTP、TLS（含 JA3 类字段）、DNS、SSH、SMB 等，tshark/dpkt 为核心解析器，
并可解析 Zeek/Suricata 日志。数据侧：文本/CSV/TSV/JSON/XLSX/SQL dump 等结构化与非结构化格式。

**Q8 检查能不能按计划跑？**
能。检查任务支持扫描配置（路径、排除项、类型、资源上限、周期），探针侧任务支持下发与断线幂等回传；
平台侧任务中心可看排队/运行/成功/失败，可中止。

**Q9 密码合规这块的依据？**
商用密码应用安全性评估参照 GB/T 39786，平台可从探针采集的服务 banner 与 TLS 握手自动填充分组密码
算法/套件/协议/密钥长度，并识别无认证、弱口令类风险，评估输入不靠人工编。

**Q10 卸载会不会残留？**
不会。卸载脚本按固定白名单删除：systemd 单元、运行目录（代码+venv）、配置与凭据目录、数据目录
（spool/规则/缓存）、安装时自带的抓包工具副本、以及本探针创建的账号；符号链接只删链接本身。
删除前先停止并禁用服务、清理仍在运行的探针进程。脚本幂等，重复执行安全。删除清单与释放空间
（文件数/字节数）回传平台留档。

**Q11 删除目标会不会被篡改导致误删？**
不会。删除目标只来自脚本内的固定白名单，**不读命令行参数、不读目标机上的文件**——因为以 root 身份
按可变文件内容删除，等于把提权原语交给攻击者。实测故意构造非法标记时，脚本拒绝删除并上报部分清理。

**Q12 审计追踪到什么程度？**
平台记录操作审计（操作人、动作、目标、结果、时间），当前写入口覆盖数据资产重建/回填等管理动作，
部署与回收全过程有独立事件时间线（每阶段一条，序号唯一递增）。若需要"所有变更操作全量留痕 + 列表页
导出"，这是我们已经规划的一步（见第 5 节）。

**Q13 能不能对接我们既有的安全设备/平台？**
能。平台留有集成适配层（Zeek、Suricata、Presidio、MISP、osquery/Wazuh、OpenSCAP 等），
离线资源中心支持规则/IOC/CVE/模型的导入导出与版本管理。

**Q14 一台主机到出结果要多久？**
演示口径：部署 30 秒内；小目录（百级文件）检查分钟级；结果实时进入检测与事件流水线。

**Q15 和商用的敏感信息发现产品比，我们差在哪？**
坦白讲：对方在存储/数据库/终端全盘接入、OCR 图片文字识别、公文与印章等专用分类器、以及带宽忙闲时
控制上更成熟。我们的强项在旁路轻量部署、流量原始取证、以及"检查能力可远程下发与回收"的闭环。

## 4. 与《SIMP-SRD-数据安全合规检测系统操作手册-敏感信息发现》的对比

### 4.1 相同点

- 都围绕**敏感信息发现**这一合规检查主线：信息源 → 识别模型 → 检查规则 → 检查任务 → 事件与结果。
- 都支持自定义识别能力：关键字类模型、正则类模型、以及内置/预置模型，并可组合成检查规则。
- 都提供多种检查任务形态：对存储/文件、对网络流量、对终端主机。
- 都是私有化部署，检查过程与结果数据留在内网。

### 4.2 差异对照

| 维度 | SIMP-SRD（手册口径） | 数据安全工具箱（现状） |
|------|----------------------|------------------------|
| 信息源 | 文件共享、数据库、网络、终端；含 Exchange/Sharepoint/Lotus/WebDAV/云对象存储 | 探针下发目录采集、主机资产与 banner、网络流量（PCAP/实时）、文件上传分析 |
| 识别模型 | 关键字（单个/关键字对/关键字组，支持模板与 TXT 批量导入）、匹配模式（正则）、其余模型（分类器/数据识别） | 规则集（146 条，含 PII 正则、密钥熵、YARA）、数据类型中心、敏感度分级、可选 Presidio 中文 PII |
| 规则表达 | 模型间逻辑组合：匹配所有/匹配任一/最小匹配个数/自定义逻辑；网络监控支持分值模式（命中分值+基础分） | 规则集 + 引擎流水线（15 个引擎）加权评分 + 置信度；规则集支持版本发布与 SHA256 回滚 |
| 任务类型 | 存储检查、网络监控、终端扫描；高级配置含生效时间、OCR、类型/日期/大小/带宽过滤 | 扫描配置（路径/排除/类型/资源上限/周期）、探针任务、主动网络扫描、PCAP 分析与实时流量、检测流水线 |
| OCR / 图片内容 | 支持 OCR（bmp/png/jpg/jpeg）与身份证、源码、印章、红头文件、公文等扩展识别 | 支持图片与扫描版 PDF 的 OCR（tesseract `chi_sim`，单文件 20 页 / 20 万字符上限），并按「版式红头 × 公文文字」判定红头文件/公文、按 `密级★期限` 等标志判定涉密文件（`DATA_CLASSIFIED_001` / `DATA_REDHEAD_001`）；**身份证等证件专用分类器暂缺** |
| 流量取证 | 以事件与命中结果为主 | 数据包分层树 + 原始字节、TCP 流跟踪、会话与五元组、协议分布（强取证） |
| 部署形态 | 组件化接入（终端组件客户端 + 多类信息源接入），需在各系统部署组件 | 单个轻量探针 + 平台；SSH 一键下发，检查后可一键回收且目标主机零残留 |
| 权限与安全 | 未在手册中展开 | 只读采集、低权限账号、不跟随符号链接、删除白名单、凭据用后即毁 |
| 审计留痕 | 事件查看（检查命中事件） | 操作审计 + 部署/回收全过程事件时间线（阶段级） |
| 交付物 | 检查事件与结果页面 | 检测结果/事件（含 ATT&CK 映射）+ HTML/PDF/CSV 报告 |

### 4.3 我们的优势点（汇报时优先讲这四条）

1. **部署与回收闭环**：一次 SSH 即可下发，检查完一键回收，卸载清单与释放空间回传留档，
   受检主机不残留服务、文件与账号——这是"服务化交付"的关键，也直接回应客户最担心的"装了东西谁去清"。
2. **证据链更硬**：结论可下钻到原始字节、会话流、文件哈希与规则版本指纹；合规检查最怕"只给结论不给证据"。
3. **一体化而非拼装**：资产、数据、协议、流量、日志、威胁情报、风险、事件、报告一条流水线，
   15 个引擎统一接口，不需要在客户现场拼多套产品。
4. **轻量无侵入**：单进程只读探针，不解密 HTTPS、不在线阻断、不改动受检网络行为；
   资源上限全部可配置，适合生产网内部署。

### 4.4 对方的优势点（被问到要正面承认）

信息源种类更全（Exchange/Sharepoint/Lotus/WebDAV/云对象存储/终端全盘）；
证件级专用分类器（身份证等）与 Office 文档**内嵌图片**的文字识别——我方已支持通用 OCR 与
红头/公文/涉密标志判定，但这两块仍是他们的强项；
规则表达更细（模型间逻辑组合、分值模式）；扫描带宽忙闲时控制与更细的过滤条件。

## 5. 未来展望

### 近期（可作为本次汇报的承诺项）

1. **审计留痕闭环**：把全量变更操作（部署、回收、规则发布、扫描配置修改、探针删除）写入操作审计表，
   并在「安全审计」页增加轨迹列表与导出。
2. **识别模型对齐 SRD 表达力**：关键字组/关键字对、模型间逻辑组合（与/或/最小命中数）、分值模式阈值。
3. **结果侧闭环**：敏感发现明细分页与导出、整改状态跟踪（待整改/整改中/已复核）。

### 中期

4. **OCR 与图片内容识别（部分完成）**：图片与扫描版 PDF 的 OCR、红头文件/公文/涉密标志判定已落地
   （见 4.2）；**仍缺**身份证等证件专用分类器，以及嵌入在 Office 文档内的图片识别。
5. **信息源扩展**：共享目录（SMB/NFS）、数据库直连、对象存储，把"文件共享/数据库信息源"补齐到同等水平。
6. **性能与规模**：大 PCAP 分片索引、增量扫描（只扫变化文件）、扫描窗口与带宽控制。

### 远期

7. **合规条款映射**：把检测结果映射到等保 2.0 / PIPL / GDPR 条款，输出"条款级符合性报告"。
8. **与既有合规系统互通**：规则与结果的双向导入导出，成为客户既有 SRD 体系的补充取证与流动数据检查手段。

## 6. 演示风险与兜底

| 风险 | 影响 | 兜底做法 |
|------|------|----------|
| 受检主机（探针）不在线 | 第三幕无法现场下发 | 提前确认在线；否则改用历史部署记录讲流程 |
