# 网络防泄密（NetDLP）检测质量与告警阈值

## 问题背景

在 Docker / 容器主机上旁路抓包时，容器之间的明文流量（HTTP 头里的 IP 与日期、JSON 中的时间戳与序列号、
Redis RESP 报文等）会被逐条识别为敏感数据并产生 High 告警，表现为"所有 Docker TCP 出站流量都告警"。

根因有两个：

1. 只要任意一条规则命中，就产生固定的 `DLP_TRANSFER_001` High 告警，命中规则本身的精度不参与判断。
2. Presidio 官方静态规则库是全球身份规则集合，其中既有定位符（IP、MAC、日期），也有低精度模式
   （`\b\d{9}\b`、车牌、各国外籍证件号）。这些模式会命中普通载荷文本。导入时若被批量启用，
   任何明文 TCP 流都会被判为敏感传输。

## 修复方式

- **规则置信度**：每条规则带 `confidence`（0~1）。Presidio 导入时取官方 `score`；早期未保存分数的规则
  按其名称标记回退（very weak/very low=.1、weak=.25、low=.3、medium=.55、high=.85）；
  人工规则默认 .7；上游无标记的规则按 .5 处理（可作证据、不告警）。
- **敏感实体分类**：`IP_ADDRESS`、`MAC_ADDRESS`、`DATE_TIME`、`URL`、`NRP`、`LOCATION` 只是定位符，
  永远不会单独使一条流变成敏感传输，但仍保留在传输证据的 `matches` 中。
- **告警闸门**：只有"敏感实体 + 置信度 ≥ `min_confidence`（默认 0.6）"的命中才产生 `DLP_TRANSFER_001`。
  命中的置信度会成为finding 的置信度，风险评分因此按规则精度缩放。
- **主机内部流量**：回环、链路本地、未指定与组播地址之间的流不计为数据外发，计入
  `coverage.excluded_streams`；可通过 `exclude_cidrs` 追加网段（默认 `127.0.0.0/8`、`::1/128`）。
- **二进制载荷**：非 HTTP 的可打印比例低于 90% 或含 NUL 的载荷不再按明文文本扫描，避免二进制协议产生
  虚假匹配。
- **宽松模式校验**：Presidio 邮箱模式只要求 `@`，会把 `postgresql://security@172.18.0.2:5432` 判为邮箱；
  现要求域名以 2 位以上字母顶级域结尾。

## 策略配置

「数据安全 → 网络防泄密 → 检测策略」：

- `min_confidence`（告警最低置信度，默认 0.6）：低于该值的规则只在传输证据中显示"（仅证据）"。
- `exclude_cidrs`（忽略网段）：每行一个 CIDR，如 `169.254.0.0/16`；回环、链路本地与组播始终忽略。
- `min_matches`（最少命中次数）：命中次数下限，与置信度无关。

规则库表格新增「置信度」与「可告警」列，可据此判断某条规则是否会产生告警；重新导入 Presidio 会按官方
`score` 刷新各规则置信度，并只默认启用可告警的规则。

## 影响与兼容

- 已保存的策略文档缺少新字段时按默认值补齐（`GET /api/v1/dlp/policy` 返回生效值）。
- 内置类别置信度：身份证 .9、API 密钥 .95、邮箱 .85、银行卡 .85、手机号 .7；`token`（任意 32 位以上
  随机串）为 .3，只作证据，避免把哈希、Base64、容器 ID 判为泄露凭据。
- 历史 PCAP 可重新分析以应用新策略。
- 无需数据库迁移。
