# 数据资产：后续功能修改入口

适用：数据资产采集与展示解耦后的代码。使用者提出业务需求，AI 应先按本表定位最少必要模块。
本轮保留全部接口、表结构、探针协议和页面交互；没有修改采集规则或修复历史数据。

## 从需求定位文件

| 业务需求 | 首选入口 | 必须一并核对 |
| --- | --- | --- |
| 修改采集表单和采集进度提示 | `frontend/src/modules/data-security/composables/useDataAssetCollection.ts`，页面 `DataAsset.vue` | `frontend/src/api/probes.ts` 的 payload 类型、取消/部分完成提示 |
| 修改列表筛选、加载、详情状态 | `frontend/src/modules/data-security/composables/useDataAssetList.ts` | 后端总数、字段数和样本命中数单位 |

| 修改身份判断 | `data_objects/identity.py` | 完整哈希/部分指纹/本地范围身份不能混淆 |
| 修改覆盖范围/时间顺序 | `data_objects/coverage.py` | 部分扫描不得让实例退役 |
| 修改检测证据合并 | `data_objects/evidence.py` | 不存原始敏感值，样本行与样本值上限区分 |
| 修改旧资产页投影 | `data_objects/projection.py` | 这是派生展示，不是原始事实来源 |
| 修改数据类型/对象/实例统计 | `data_objects/queries.py`、`api/data_catalog.py` | 跨类别去重、分级覆盖、在位/历史分开 |

`data_objects/` 缩写路径均位于 `backend/app/services/`。

## 不要重新引入的依赖

- 业务路由不能再从 `api/extensions.py` 导入鉴权或任务创建。鉴权在 `api/dependencies.py`，建任务在服务层。
- `services/probe_task_service.py` 抛领域异常；404/409 由 `api/error_handlers.py` 转换，不在服务里引入 FastAPI。
- `data_objects` 各模块不能导入旧 `data_object_service.py` 门面、HTTP 路由或 Celery worker。
- 旧门面只为历史脚本/测试重导出符号，不新增业务实现；新增生产调用应直接导入对应模块。
- `persistence.py` 负责公共数据库原语；它和 ingestion/projection 不 commit，由现有 HTTP 调用方提交。
  创建采集任务仍保持原有服务内部 commit 时点。本次未统一或扩大事务。
- 页面组装 composable，列表和采集通过完成回调联系；不要让采集逻辑直接修改列表 filters/items。

## 让 AI 修改时提供的信息

给出目标页面或接口、现有行为、期望行为和一条真实业务例子即可。例如：
“数据资产页采集时要允许排除目录；已排除的目录不应被采集；任务中心要显示实际下发的排除条件。”
AI 应先核对现有 `exclude_paths` 端到端支持，避免又实现一套平行参数。

执行顺序：定位入口 → 明确兼容影响 → 改最少模块 → 跑相关行为回归 → 更新文档中的当前状态。
涉及探针采集能力时，平台前端支持不等于探针已经执行；必须明确探针协议/分发包/版本影响。

## 最小回归

后端隔离环境执行：

```text
python -m pytest tests/test_data_asset_boundaries.py tests/test_data_objects.py tests/test_data_asset_probe_api.py tests/test_scan_profiles.py tests/test_probe_task_lifecycle.py tests/test_ruleset_release.py tests/test_probe_delete.py
```

前端执行 `npm run typecheck` 与 `npm test -- --run`。新增 `data-asset-state.test.ts` 锁定
采集 scope 参数、Partial/Cancelled 提示与刷新行为，以及详情字段数/命中数和列表总数；
`data-asset-jobs-state.test.ts` 锁定任务列表 kind、派发 payload 优先级、取消/移除与轮询开关。
新增 `test_data_asset_boundaries.py` 防止模块循环依赖、业务路由互相导入以及服务倒依赖 HTTP/worker。

发布前全量测试失败要与同环境基线逐项对比；不能把新增失败归入历史环境问题。
真实环境只读验收列表/详情/健康状态，禁止测试导入、假数据构建和未授权的真实探针命令。
