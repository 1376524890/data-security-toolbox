## 变更范围

- **一键离线部署套件（本版主交付）**：新增 `deploy/`——`deploy.conf` 是**唯一配置入口**（全部参数带中文注释、
  按段分组，`auto` = 首次生成以后沿用，优先级 命令行 > 文件 > 内置默认）；`deploy.sh` 在终端里先**交互式**
  问一遍现场必须定下来的项（项目名、数据目录、控制台/API 端口、探针回连地址、管理员账号、数据库名与用户、
  五个口令与密钥、可选的通知/情报/主机审计集成），回车取 `deploy.conf` 的值、口令留空则自动生成，
  然后打印确认摘要，确认后**非口令项写回 `deploy.conf`**（行尾注释保留）而口令只进 `.env`（`chmod 600`）。
  随后一条命令跑完：环境自检（docker / compose v2 / 必须是 aarch64）→ `docker load` → 生成 `.env` →
  把 `deploy-data/backend` 授权给容器用户 10001（无 root 时用包内 `redis:7.4-alpine` 跑 chown，
  否则 API 会因 `PermissionError: '/app/data/storage'` 反复重启）→ 端口预检（仅当本项目还没有容器）→
  `docker compose up -d --no-build --pull never` → 等 backend 健康 → 打印地址/口令/数据目录。
  `--non-interactive` 走全自动（stdin 不是终端时自动如此），`--dry-run`、`--force`、端口/地址/口令等
  命令行覆盖照旧；`undeploy.sh` 停栈保留数据，`--purge` 二次确认后删数据目录。
  交付包里有 `.env.example`（变量模板与说明）但**没有 `.env`**：打包脚本显式排除操作者本机 `.env`，
  否则会把构建机的口令与现场 IP 带到每一个交付点。
- **数据安全态势大屏**：`/` 换成整页 1920×1080 深色大屏（`meta.layout='screen'`，不渲染侧边栏与顶栏），
  6 张 KPI 卡、数据流动势态拓扑、两条 7 天趋势、两个分布环、引擎/探针运行状态、事件闭环与自动滚动的
  实时事件流；`/screen` 重定向到 `/`，旧链接不落空。
- **数据安全综合驾驶舱**：新增 `/cockpit` 作为日常使用页（在控制台壳层内），8 张 KPI 卡、健康度环、
  资产/风险两个分布环（可切维度）、合规进度板、本周重点关注、安全流水线、数据流动卡片与最近任务。
  两个首页共用同一条 `GET /dashboard/overview`（驾驶舱块为增量），因此同一时刻不可能对不上数字；
  判定口径集中在 `services/cockpit_service.py`。
- **浅色控制台与图表主题联动**：控制台改为默认浅色（只有 `dst-theme === 'dark'` 才深色）；主题状态提到
  `frontend/src/utils/theme.ts`，`components/charts/{Bar,Donut,Gauge,Trend}Chart.vue` 监听 `themeMode`
  重建 ECharts option（option 构建时就把颜色写死，不重建会在浅色页留下深色网格）；壁挂大屏不受主题影响。
- **新增接口**（全部按 `app/models.py` 的行实时聚合，不落缓存、不写死）：`GET /dashboard/overview|traffic-flow|risk-distribution|detection-trend`、
  `GET /dashboard/trend?range=7d|24h`、`GET /dashboard/tasks?limit=`；`GET /alerts` 增 `order=recent`
  （默认顺序不变）；`GET /network/assets`、`GET /network/assets/summary`；
  `GET /offline/cves/fingerprints`、`POST /offline/cves/sync`；政策组 `/policy-groups*` 与只读评估 `/assessments*`。
- **CVE 规则库**：NVD 导入保留产品与受影响版本区间，并解析 CVSS v3.1 / v3.0 / v2，使扫描结果能**确认**
  某个 CVE（而不只是提示）；漏洞库页面可见指纹与命中依据。
- **网络资产**：端口扫描结果与 CVE 库存汇总成一张清单（`network_assets`）。
- **出境明细**：每笔外传绑定到具体文件、命中的规则原文与报文；新增离线 CIDR→国家/地区表
  （`backend/app/services/data/egress_regions.json`，由 `scripts/build_egress_regions.py` 生成），
  出境判定不再依赖在线库。
- **任务中心向导化**：任务中心改为「列表 + 分步下发向导」，目标可达性测试与目录树浏览做成同步接口。
- **监控任务分段归集**：探针连续抓包产生的 30 秒分段归属于其所在探针的长生命周期 `monitoring` 任务
  （`payload.monitor_task_id`），`/tasks` 默认隐藏分段；分段计数按子任务实时重算，不落库当真相。
  修复前一个探针几分钟就能刷出 39 条任务行，把别的任务全埋掉。
- **高发风险文件 → 规则候选指纹**：高风险文件可沉淀为候选指纹，人工确认后进入规则。
- **菜单收敛**：数据安全相关页面收敛为六个顶级条目；合并后的数据资产页与资产中心各自只保留一处实现。
- **探针缺陷修复（真机端到端发现）**：
  - `probe/probe.py` 的 spool 清理原先被 `uploaded_any` 门控——spool 满时没有新东西可传，`uploaded_any`
    恒为 `False`，清理永不执行 → spool 卡在 2048 MB 上限、抓包降级死锁（真机上 2021 段 / 2068 MB）。
    现在每轮上传循环都执行保留策略，真机复验 spool 从 2021 段降到 36 段、抓包一分钟内恢复。
  - `scripts/build_probe_packages.py` 增 `--arch=`，只有一个运行时的构建机也能出包。

## 已知边界

1. 流向只报「内部流量 / 外部流出 / 目的未识别」三类——数据模型里没有 zone 表，就不做「跨域访问」这一档；
   `external` 仅在地表或黑名单命中时成立，未证实的目的地保持黄色「未识别」而不是当成出境告警。
2. 目的地址为内网时曝光度按 2.0 计分 → DLP finding 可能低于 `high_finding_min_risk` 而不产生告警，
   命中只在网络防泄密页可见（口径未改，未擅自放行人工规则）。
3. 重建镜像需要外网（pip / npm 要拉包）；离线环境上继续开发用「源码挂载 + 重启」，
   需要新镜像时在有外网的构建机上按 `README-离线部署.md` 第六节重建。
4. 集成组件（Zeek / Suricata / MISP / Wazuh）是可选 profile，默认不启动，不影响主流程。
5. 本机浏览器自动化不可用，页面点击验收需人工按包内 README 第四节清单点选。
6. 探针 3.7.0 分发包已随包产出，本次发布**未对任何真实主机升级探针**。
