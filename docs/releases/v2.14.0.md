## 变更范围

- **统一规则源**：新增 `backend/app/services/sensitive_engine.py`，控制台手写规则（`analyst_rules()` 读规则库）
  与探针内置规则（`scan_engine()` 按 mtime+size 签名重建）在平台侧合成同一份引擎；`scan_all()` 一次扫描
  供文件扫描、数据库扫描、DataEngine 与网络防泄密四个消费方复用。手写规则由此在
  「敏感发现 / 实时流量告警 / 网络防泄密」三处命中口径一致。
- **命中原文**：`DetectionHit.matches` 增补 `value` / `context`；平台侧
  `services/data_objects/evidence.py` 与探针侧 `shared/sensitive_detection/engine.py` 各自按
  ≤3 条 / `value` ≤120 / `context` ≤240 字符重裁，`report_guard` 把 `matches` 列进 `RAW_TEXT_KEYS`。
  网络防泄密的传输对象、DLP finding 与告警证据同样带 `matches`。
- **共享文件来源**：`backend/app/services/file_scan/` 与 `backend/app/api/file_sources.py` 支持
  FTP / FTPS / SFTP 只读采集；来源可新增、修改（含共享目录）、删除与连通性测试；迁移 `0017_file_sources`。
  适配层对不支持 `MLSD` 的服务器回退 `LIST`。
- **数据库直连盘点**：`backend/app/services/database_scan/` 与 `backend/app/api/database_connections.py`
  支持只读直连 MySQL/MariaDB（PyMySQL）与 PostgreSQL（psycopg2），迁移 `0016_database_connections`。
- **采集语义与止增**：`shared/scanning/budget.py` 拆分 `enumeration_complete` / `content_complete`；
  DataEngine 不再把原始抓包容器登记为文档资产；`scripts/audit_capture_assets.py` 只做只读审计。
- **前端**：新增「来源管理」「资产目录」「数据库连接」页面与对应 composable；检测证据抽屉展开显示命中原文。

## 已知边界

1. 目的地址为内网时曝光度按 2.0 计分 → DLP finding `risk=51 < high_finding_min_risk=60`，不产生告警；
   命中只在网络防泄密页可见。是否对人工规则单独放行尚未决策，未擅自改动。
2. 在线探针若仍是旧版本，其上报证据没有 `matches`（页面显示「没有回传原文」）。
3. PostgreSQL 直连与 MySQL 走同一适配层，但本批没有真实 PG 目标，只有隔离测试，不宣称已验证。
4. 探针 3.6.0 分发包已产出，但未在任何真实主机上执行升级。
5. 浏览器点击验收未自动化（本机浏览器自动化不可用），需人工按交付包 README 第四节清单点选。

变更与验证要点：

- **探针自带运行时**：包内私有 CPython 3.11 + `requests`/`psutil`/`regex`/`openpyxl` + `dumpcap`/`tcpdump` +
  ELF 库闭包 + 私有加载器（`--inhibit-cache --library-path`）+ CA 证书；安装不执行 pip/apt，不写
  `/usr/local/bin`；平台预检用同一运行时（上传目标机、比对 sha256、跑 `runtime_check.py`）。
- **不依赖目标环境**：`ExecStart` = `/opt/data-security-toolbox/run-probe.sh`，只用 shell 内建命令定位目录、
  自设 `PATH`，并固定 `PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8`（systemd 启动时 `LANG` 未设置会让 CPython 退回
  C 语言环境、stdio 按 ASCII 处理，中文日志会被转义甚至报错）；随包单元模板与 `install.sh` 生成的单元都写入
  这两个变量；`install.sh` 先检查主机工具（`tar`/`systemctl`/`useradd`/`id`/`chown`/`find`/`dirname`/`mktemp`）；
  `runtime_check.py` 校验运行时布局完整性并断言解释器来自包内 `python/`（`sys.base_prefix`）。
- **验证证据**：amd64 包在 `--network none`、无 python3/pip/dumpcap 的 `ubuntu:22.04` 容器内跑通离线安装冒烟
  （真实 `dumpcap` 抓包、`/proc/self/maps` 无 runtime 外 .so、76 个自带扩展模块全部可导入、空环境 + `LANG=C`
  下启动器可用、UTF-8 中文落盘、重装保留 `probe.token` 与 spool、`--keep-data` 卸载保留数据）；同一份 arm64 包
  在 qemu 下除抓包外全部通过（qemu-user 不能翻译 libpcap 的 socket ioctl，属模拟器限制，冒烟显式 SKIP 而不
  误报）。后端 `tests/deployment` 63 项全通过；交付包 `verify_bundle.py` PASS（1005/1005 校验和、0 个非法
  UTF-8 名、0 个缺可执行位）。
