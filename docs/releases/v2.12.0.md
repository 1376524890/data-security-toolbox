## 升级与回退边界

1. 在其他环境升级前，备份数据库和文件存储并验证恢复能力。先确认当前迁移版本，保留旧镜像摘要。
2. 本版新增建表/加列迁移，按既有部署流程应用 `0015_alert_hits`；不要手改库、不要回改已发布迁移。
3. 代码发布不会自动修复全部历史计数、告警命中和投影；现有只读 `scripts/remediation_dry_run.py`
   用于列出差异，历史修复应另立任务，在备份、差异复核和审计齐备后执行。
4. 回退代码不等于回退数据。`0015_alert_hits` 的 downgrade 会删除命中表和样本上限列，
   不作为常规自动回退步骤；先在隔离恢复库验证旧代码能否兼容保留的新结构。
5. 发现回归时停止推广；保留当前数据与审计，通过新修复提交或经验证的旧镜像回退处理，不重写历史标签。
