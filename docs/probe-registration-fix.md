# 探针注册流程修正

## 检查结论

`source` 后端已有 SSH 下发、安装、一次性注册令牌和首次心跳闭环，前端也已有独立部署页；但探针中心仍使用旧的 `/probes/register` 接口创建 `manual / 0.0.0.0` 记录。该接口应由目标主机上的探针自行调用，不能作为管理员下发入口。

## 当前操作

探针中心 → 注册探针 → 填写目标主机 IP、SSH 端口（默认 22）、用户名、密码 → 注册并自动下发。
名称可选，默认 `probe-目标IP`；默认使用密码认证和 standard 模式。下发后自动打开详情，每 3 秒刷新进度。收到首次心跳后显示 ONLINE，可返回探针中心。失败重试会带入原目标，必须重新输入凭据。提交成功或关闭表单会清空凭据。

## 后端修正

- 创建任务和加密凭据在一次事务中提交；缺少加密配置时明确拒绝，避免遗留空任务。
- 重试检查原目标、密码认证策略、配置和同主机活动任务，并清除旧回调时间。
- 安装及启动支持 root 或免密 sudo；检查解包、启动返回码。
- 私钥口令随私钥一起加密并传递给 SSH 客户端。
- 配置中的 CA 使用目标主机安装路径。
- 已注册但未收到首次心跳的任务也会超时；避免启动后的进度覆盖并发心跳结果。

## 运行前提和交付范围

修改位于 `source`，旧的 `dist-deploy` 目录和 ZIP 未更新。使用旧部署包的环境需按项目发布流程重新构建前端、后端及 deployment-worker，并应用 0008 数据库迁移。
平台必须配置 DEPLOYMENT_SECRET_KEY、DEPLOYMENT_BACKEND_URL、探针安装包以及 SSH 主机信任配置；目标为满足预检条件的 Linux/systemd 主机，账户为 root 或支持免密 sudo。未提供真实目标主机，本次没有执行实机下发。
